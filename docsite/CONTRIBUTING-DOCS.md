# Where documentation lives

Every push to `master` rebuilds and publishes the site (`.github/workflows/docs.yml`). Nothing generated is committed.

- **API reference:** XML doc comments (`///`) in the code. DocFX renders `summary`, `remarks`, `param`, `returns`, `exception`, `example`, `seealso`, `cref` and `inheritdoc`.
- **Code examples:** compiled samples in `docsite/samples/` inside `#region name` ... `#endregion`. In an article use `[!code-csharp[](../samples/File.cs#name)]`. In an XML comment use `<example><code source="<path from the .cs file>/docsite/samples/File.cs" region="name" language="csharp"/></example>`.
- **Articles:** add a markdown file to `docsite/articles/` and one `- href: file.md` line to `docsite/articles/toc.yml` (the menu title is the file's first heading).
- **Namespace and package overviews:** a markdown file with `uid: <namespace>` and `summary: *content` front matter. Put it in `Source/<Project>/docs/` next to the code, or in `docsite/api/overview/`; both are picked up without a config edit.
- **Diagrams:** a standalone `.svg` in `docsite/images/`, colors as CSS variables, no external references.
- **Side-by-side comparisons:** wrap two markdown code blocks in `<div class="side-by-side">` (one `<div>` per column, blank lines around the content, styled by `templates/custom/public/main.css`). Both regions need the same number of lines so the rows align.
- **README.md:** a pitch with absolute links; its code blocks are copied from sample regions.
- **Package READMEs:** each `Source/<Project>/README.md` is the page nuget.org shows for that package (`Source/Directory.Build.props` packs the one beside the `.csproj`). Absolute links only, code blocks copied from sample regions. The "The packages" table is the same in every one of them: change it in all of them together.
- **Package heroes:** the banner directly under the H1 of each package README is `docsite/images/hero-<package>.svg` (1280 by 200; Core is 260). Left column: the ODX mark (a database and the letters ODX, in the package's accent color) with the package name; then the tagline; then a small scene. ODX is the acronym and the mark, not the name. The site name (`_appName` and `_appTitle` in `docfx.json`) and the H1 of the root `README.md` say "Open.Database.Extensions (ODX)"; the landing page `docsite/index.md` has no H1, by design (the header shows the name and the banner says what the library is, with its alt text as the accessible name; its front matter `title` is the browser-tab title); the package README H1s and all prose keep the full name Open.Database.Extensions. The banner's alt text carries the tagline; never repeat the tagline as text next to a banner. Each is linked by its absolute `raw.githubusercontent.com` URL because nuget.org shows only images from allow-listed hosts (that host is one). Each paints its own soft background in a light and a dark palette (`prefers-color-scheme`), because nuget.org's page theme can differ from the operating system's; keep the contrast soft and any motion subtle (`prefers-reduced-motion` turns it off).
- **Build locally:** `dotnet tool restore`, then `dotnet docfx docsite/docfx.json --serve`.
- **Failures:** warnings are listed in the workflow summary and never block a deploy. A DocFX error or a sample that does not compile does, and the live site stays as it was.
