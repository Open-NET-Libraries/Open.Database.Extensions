# What's new in 11

> [!NOTE]
> Version 11.0.0 is currently a preview (`11.0.0-preview06`). Please try it and report what you find.

Version 11 is a performance release. Result mapping is rewritten around a cached, typed row reader. See [Performance](performance.md) for what that does and does not buy you.

## Preview 06

New since `11.0.0-preview05`:

- **Fix: `AddParam("name", someString)` could send the name and the value swapped on a compiler older than C# 13 (the .NET 8 SDK),** in `11.0.0-preview05`. The call bound the overload that takes a parameter's name from the argument text, so `AddParam("author", "ann")` sent a parameter named `ann` with the value `author`; `AddParamIf` did the same. New `AddParam(string, string?)` and `AddParamIf(bool, string, string?)` overloads fix it: the name you write is used on every compiler. If you are on `11.0.0-preview05` with an older compiler, pass a non-string value or upgrade. A compiler older than C# 10 does not supply the argument text that `AddParam(value)` needs, and now gets an `ArgumentException` that says so.
- **A token passed to an async terminal covers the whole call.** `ToListAsync(token)` and the other async terminals of `Map<T>()` (including both `ReadAsync` overloads) use `token` together with the command's `UseCancellationToken` token, and either one cancels the call. Before, `token` reached only the row reading, so it could not cancel opening the connection, looking up stored-procedure parameter names or executing the command. `IExecuteReader` has a new `ExecuteReaderAsync` overload that takes the token for the call; if you implement `IExecuteReader` yourself, add it. See [Terminals](expressive-commands.md#terminals).
- **Breaking change: the scalar transform overloads receive `null`, not `DBNull`, for a `NULL`.** `ExecuteScalar<T>(Func<object?, T>)`, `ExecuteScalarAsync<T>(Func<object?, T>)` and `ExecuteScalarAsync<T>(Func<object?, ValueTask<T>>)` pass `null` to your function when the column is `NULL` (and for no rows, as before), so `ExecuteScalar<int?>(o => (int?)o)` returns `null` instead of throwing `InvalidCastException`. A function that tested `o is DBNull` should test `o is null`. The raw `ExecuteScalar()` and `ExecuteScalarAsync()` are unchanged and still return `DBNull.Value` for a `NULL`.
- **Parameter prefixes and field prefixes no longer need renaming.** An argument now also finds a parameter that carries a common prefix (`@p_author`, `@pAuthor`, `@in_author`, `@i_author`, `@prm_author`, `@par_author`, `@v_author`), and `m_author`, `s_author` and `_author` also try `author`. The prefix is tried for each candidate after it failed to match exactly, ignoring case, and ignoring case and underscores, so `order.Customer.Id` finds `@p_customer_id` before a bare `@id`; a name you pass yourself is always used exactly as written.
- **Constructor binding.** `Map<T>()` and every map-taking method now build positional records, record structs and classes with one public constructor through that constructor, and set the `init` and settable properties it does not cover. A parameter is fed like a property (the same column matching, the same `RowMap<T>` pairs), and a record's positional property and its parameter are one member, fed once. A `RowMap<T>` pair that names a positional property applies to its parameter, and a `null` column for it means the parameter is not read. A type with a public parameterless constructor is built exactly as before.
- **`required` members are supported and enforced.** A `required` property (an inherited one too) maps like any other, through its setter (`init` included), and every result shape needs a column for it. When none has one, the first row of that shape throws `ValueMappingException` (`No column feeds the required property 'Title' (String) of 'Post'; expected a column named 'post_title'.`); a constructor parameter's default never satisfies a `required` property. A `null` column for a required property in a `RowMap<T>` throws `ArgumentException` when the map is created. A constructor marked `[SetsRequiredMembers]` promises to set them, so nothing is enforced and they map like any other property. A `required` public field cannot be set, so its type throws `InvalidOperationException` at the call. A missing column is reported at the first row, so an empty result does not report it.
- **Breaking: `where T : new()` is removed** from every method that maps rows to a model (`Map<T>`, `Results<T>`, `ResultsBuffered<T>`, `ResultsAsync<T>`, `DataTable.To<T>`, `DequeueAs<T>`, `ToChannel`, `ToTargetBlock`, `AsSourceBlock` and the rest), so a type that cannot be mapped throws `InvalidOperationException` at the call, even for an empty result, instead of failing to compile. Interfaces, abstract classes and delegates are rejected, and so are a class with no public constructor and a type with two or more public constructors and none without parameters (use `Map(selector)` for those).
- **Breaking: a struct with one declared public constructor is built through it.** A `record struct`, or a struct with a primary constructor, used to be its default value with its settable properties set, and its constructor was not called. A `record struct` gets equal results; a struct whose constructor does more than assign now runs it. A struct with no public constructor, or a public parameterless one, maps as before.
- **Breaking: a missing constructor-parameter column gives the declared default.** A parameter no column feeds, or whose cell is `NULL` when the parameter is a non-nullable value type, receives its declared default value (`int views = 3` gives 3), else `default`; for a struct built through its constructor, that default now replaces the plain default of before. A `NULL` into a nullable parameter is `null`, as it is for a property; for a parameter the type declares non-nullable, see the next bullet.
- **Breaking: a `NULL` no longer overwrites a member the C# type declares non-nullable.** With nullable annotations on, `string Name { get; set; } = "";` keeps `""` when the column is `NULL`, and a constructor parameter `string title = "n/a"` gets `"n/a"`, as a non-nullable value type already did. A property with no initializer stays `null`, and a parameter with no declared default gets `null`. `Nullable<T>` (`int?`), a reference declared nullable (`string?`, or `[AllowNull]` on a property), a reference type in code with nullable annotations off, and a member declared as a type parameter (`T Value`) are unchanged: a `NULL` gives `null`. Before: a `NULL` always gave a reference-type property `null`, whatever its initializer. Now: declare the property `string?` to get `null`.
- **Breaking: `Map<int>()` and the like now throw** `InvalidOperationException`; they used to return default objects. A single value (`int`, `string`, `decimal`, `Guid`, an enum, `byte[]` and the rest) is not a row model: use `ExecuteScalar<T>()` or `FirstOrdinalResults<T>()`.
- **Breaking: `RowMap<T>.Default` is a property,** not a field, so reading it throws `InvalidOperationException` for a type that cannot be mapped.
- **The async transaction helpers and the SQL Server `ExecuteReaderAsync` overloads no longer resume on the caller's synchronization context.** `ExecuteTransactionAsync`, `ExecuteTransactionConditionalAsync` and the `ExecuteReaderAsync` overloads of the two SQL Server packages now await with `ConfigureAwait(false)`, and so does the connection open they trigger. A caller that blocked on one of them from a thread with a synchronization context no longer waits on that context inside the library.

## Preview 05

New since `11.0.0-preview04`:

- **Name a parameter from its argument.** `AddParam(search.Author)` and `AddParamIf(condition, search.Author)` take the parameter name from the argument expression (a variable or a chain of properties and fields). For a stored procedure the provider reports the real parameter names and the argument is matched to one (exactly, ignoring case, ignoring case and underscores), so `TitleContains` finds `@title_contains`; SQL Server is supported in both SQL Server packages. `AddParams(source)` sends the public properties and fields of the static type of `source` that the procedure declares. See [Parameters](expressive-commands.md#name-a-parameter-from-its-argument).
- **The token-only `DbDataReader` overloads are back.** `ResultsAsync<T>(CancellationToken)` and `ResultsBufferedAsync<T>(CancellationToken)` are available again; they were not in `11.0.0-preview04`.
- **A parameter with no value is now sent by both SQL Server packages.** It was never added to the command, so an output parameter (`AddParam(name, direction)`) never reached SQL Server. SqlClient needs a type and size for an output parameter and refuses the command without them.
- **A `NULL` is sent with the type of its argument,** for the new `AddParam(value)` and `AddParamIf(condition, value)`, so SQL Server does not have to guess the type of a bare `NULL`.

## Preview 04

New since `11.0.0-preview03`:

- **`RowMap<T>` can be declared with the collection syntax.** `public static RowMap<Post> PostMap => field ??= [new(nameof(Post.Id), "post_id"), ...];` takes one pair, several, or none (none maps by name, like no map). A map enumerates the pairs it was declared with, so `new RowMap<T>(map)` makes an equal copy. See [Columns named differently](mapping.md#columns-named-differently).
- **A single pair works in the constructor.** `new RowMap<T>(new("A", "b"))` compiles and maps. In preview03 it did not compile, and the pair needed brackets.
- **The `ValueMappingException` message names the target type:** `Unable to set value of property 'Id' (Int32) from column 'id'.` (`Int32?` for a nullable property). The properties of the exception are unchanged.
- **Documentation corrections.** Corrected statements that were false or misleading (a `NULL` keeps the property's initializer, else its default; exception handling; the README on who opens the connection), stated the three column-matching tiers the same way everywhere, and turned the NULL and matching examples into compiled, checked samples. The README inside the NuGet package is corrected in this version.

## Preview 03

New since `11.0.0-preview02`:

- **A `NULL` no longer throws.** A non-nullable value-type property keeps its initializer, else its default (see [NULL in a non-nullable column](mapping.md#null-in-a-non-nullable-column)). `ExecuteScalar<T>()` and `ExecuteScalarAsync<T>()` return `default(T)` for `NULL` or no rows.
- **snake_case columns map to PascalCase properties.** `Map<T>()`, and every `RowMap<T>` for the properties it does not name, now also match a column to a property by name with the underscores removed from both, ignoring case, after the exact and ignore-case matches have been settled: `q_type` feeds `QType`, `min_date` feeds `MinDate`, `address_2` feeds `Address2`. This is new default behavior: a column that used to match no property, and was ignored, can now fill one. A property that a pair names keeps its exact meaning: it reads only its column, and a `null` column opts it out. See [snake_case columns map to PascalCase properties](mapping.md#snake_case-columns-map-to-pascalcase-properties).
- **`ValueMappingException` for a value that cannot be mapped.** A failure reading a column into a property (an unconvertible value, an overflow) now throws `ValueMappingException` (a `DataException` that names the property, the column and the target type) instead of `InvalidOperationException`, so application code that treats `InvalidOperationException` as a business-rule failure no longer catches a data error. See Breaking changes.

## Preview 02

New since `11.0.0-preview01`:

- **`RowMap<T>`: declare a column mapping once.** When a query's columns are named differently from the model's properties, declare an immutable `RowMap<T>` once, from key/value pairs of property name and column name, and pass it as the `map` argument of `Map<T>`, `Results<T>`, `ToChannel`, `ToTargetBlock`, `AsSourceBlock` and every other method that maps rows to a model: `public static RowMap<Post> PostMap => field ??= [new(nameof(Post.Id), "post_id"), ...];`. A read through a map allocates what `Map<T>()` allocates on matching names. See [Columns named differently](mapping.md#columns-named-differently).
- **Only public instance properties are mapped.** A static property is no longer treated as a mappable property: name matching ignores it, and a `RowMap<T>` that names one throws when it is created.

## New and improved

- **Cached, typed row mapping.** The mapping for a result-set shape is compiled once and reused. Before, every query compiled a setter per property, which was a fixed cost of about a millisecond per `Map<T>()` in the library's own benchmark. Values are read with typed getters, so nothing is boxed.
- **Direct read loops.** `ToList`, `ToArray`, `FirstOrDefault`, `SingleOrDefault`, `ToDictionary`, `ToHashSet`, `ToImmutableArray` and their async twins read straight from the reader. `Skip` advances without mapping and `Take` stops reading once it is met. They are instance methods on `MappedQuery<T>`, so the query struct is not boxed; the `IMappedQuery<T>` extensions remain for generic code.
- **No per-call closures.** `IExecuteReader` gained state-passing `ExecuteReader<TState, TResult>` and `ExecuteReaderAsync<TState, TResult>`. Pass a `static` lambda and the state it needs.
- **Leaner commands.** A command created from a connection no longer allocates a pool wrapper, `Params` is created on first use, and async execution skips awaiting when the connection is already open.
- **Reader behavior.** `Map<T>()` opens readers with `SequentialAccess | SingleResult`, and `FirstOrDefault` adds `SingleRow` when nothing is skipped. `Map(selector)` does not use `SequentialAccess`, because a selector may read columns in any order.
- (preview06) **Constructor binding and `required` members.** Positional records and classes with one public constructor map through it, and a `required` property is enforced. See [Mapping](mapping.md).
- (preview06) **A token passed to an async terminal covers the whole call,** not only the row reading.
- (preview06) **Parameter and field prefixes.** `AddParam(author)` also finds `@p_author`, `@in_author` and the other common procedure prefixes, and `m_author`, `s_author` and `_author` also try `author`.

## Fixes

- (preview05) **`ExecuteReturn<T>()` and `ExecuteReturnAsync<T>()` return `default(T)` for a `NULL` return value,** as `ExecuteScalar<T>()` does, instead of throwing `NullReferenceException` for a value type.
- **Channels and Dataflow.** With `complete: false`, the command no longer runs twice. The mapped `ToChannel<T>`, `ToChannelAsync<T>` and `ToTargetBlock<T>` overloads complete your target only after every row has been delivered and the reader has been released (before, up to about 1,024 buffered rows could be lost with a bounded target). They no longer lose the last row when the reader fails mid-stream, and they map correctly when the reader has extra unmapped columns.
- **Connections and commands.** `OpenAsync(IDbConnection)` no longer opens a `DbConnection` twice. `EnsureOpenAsync` closes a connection that finished opening just as cancellation arrived. `FirstOrdinalResults<T>(IDbCommand, behavior)` honors `behavior`.
- (preview06) **`AddParam("name", someString)` no longer swaps the name and the value on a compiler older than C# 13.** See Preview 06 above.
- (preview06) **The async transaction helpers and the SQL Server `ExecuteReaderAsync` overloads no longer resume on the caller's synchronization context.**

## Breaking changes

Items marked (preview03) are new since `11.0.0-preview02`, (preview05) since `11.0.0-preview04` and (preview06) since `11.0.0-preview05`.

- (preview05) **`AddParam(string name, ParameterDirection direction)` and `AddParamIf(bool, string, ParameterDirection)` require the direction.** It used to default to `Input`, so a call such as `AddParam("name")` added a parameter with no value; that form now treats the string as a value and throws `ArgumentException` at the `AddParam` call, because a string literal is not a name that can be derived from its expression (see above). A single argument now names the parameter from its expression. Pass `ParameterDirection.Output` or `ParameterDirection.ReturnValue` explicitly when you want a parameter with no value.
- **One `map` parameter.** The overloads that took key/value pairs (`IEnumerable<KeyValuePair<string, string?>>`) are removed from `Map<T>`, `Results<T>`, `ResultsAsync<T>`, `ResultsBuffered<T>`, `ResultsBufferedAsync<T>`, `ResultsFromDataTable<T>`, `DataTable.To<T>`, `DequeueAs<T>`, `Transformer<T>.Create` and the `Transformer<T>` constructor. Each of these methods now takes one `RowMap<T>? map` parameter in the same position. It is optional (default `null`, which reads by column name) except on the mapped `ToChannel`, `ToChannelAsync`, `ToTargetBlock`, `ToTargetBlockAsync`, `AsSourceBlock` and `AsSourceBlockAsync`, where you pass a map or `null` explicitly (a call with no map binds to the no-map overload). Before: pass the pairs, or a `Dictionary<string, string?>`, to each call. Now: declare a `RowMap<T>` once and pass it. To keep a dictionary, build the map from it with `new RowMap<T>([.. dictionary])`. The parameter is now named `map`, so a caller that passed it by name (`fieldMappingOverrides:`) must rename the argument.
- **The value-tuple overloads are removed.** Every overload that took `(string Field, string? Column)` tuples (as `params IEnumerable<...>`, `IEnumerable<...>` or `params (...)[]`) is gone from the methods listed above (except the `Transformer<T>` constructor), from `ExpressiveDbCommandBase.ResultsAsync<T>` and from the mapped `ToChannel`, `ToChannelAsync`, `ToTargetBlock`, `ToTargetBlockAsync`, `AsSourceBlock` and `AsSourceBlockAsync` methods. Before: `cmd.Results<Person>(("FirstName", "first_name"), ("LastName", "last_name"))`. Now: declare a map once, `RowMap<Person> map = new([new(nameof(Person.FirstName), "first_name"), new(nameof(Person.LastName), "last_name")])`, and pass it, `cmd.Results<Person>(map)`. Only `Map<T>` also takes the pairs themselves, `cmd.Map<Person>(new(nameof(Person.FirstName), "first_name"), new(nameof(Person.LastName), "last_name"))`; that builds a new map on every call, so declare a map for anything that runs more than occasionally.
- **A `RowMap<T>` is checked when it is created.** Cases that were tolerated now throw `ArgumentException`: a property listed twice (the last entry used to win), an empty column name, two properties on one column, and an unknown property with a `null` column (it used to be ignored). A default (uninitialized) `ImmutableArray` of pairs, like an empty list, means no mappings.
- `IExecuteReader` has three new members: the two state-passing ones (above) and, (preview06), an `ExecuteReaderAsync` overload that takes the call's `CancellationToken`. Custom implementations must add them; the `ExpressiveCommand*` classes already do.
- (preview03) **`ValueMappingException` replaces `InvalidOperationException` for a value that cannot be mapped.** A failure reading a column into a property (a value that cannot be mapped: an unconvertible value, an overflow) now throws `ValueMappingException`, a `DataException`, instead of `InvalidOperationException`. It carries `PropertyName`, `ColumnName` and `TargetType`, with the provider's or conversion error as the inner exception. Catch the new type or `DataException`; provider exceptions (`DbException`) are still not wrapped.
- (preview03) **A `NULL` read into a non-nullable value-type property** threw in preview02 and earlier; it now keeps the property's initializer, else its default. A property that is nullable, or a reference type, gets `null`.
- (preview03) **Columns also match properties ignoring underscores.** `q_type` now feeds `QType`, so a column that used to be ignored can now fill a property. To opt a property out, give it a `null` column in a declared `RowMap<T>` (see [Columns named differently](mapping.md#columns-named-differently)).
- A pair in a `RowMap<T>` that names a property that does not exist throws `ArgumentException` when the map is created (it was `KeyNotFoundException`).
- `FirstOrdinalResults<T>` reads `NULL` as `default`. `ResultsBuffered*` and `FirstOrdinalResults<T>` still buffer into a queue and return a dequeuing enumerable, so items are released to the garbage collector as they are drained.
- `ExpressiveCommandBase.Params` is created lazily.
- Async command execution passes the command's `CancellationToken` to the connection open.
- (preview06) **The scalar transform overloads receive `null`, not `DBNull`, for a `NULL`.** A function that tested `o is DBNull` should test `o is null`. See Preview 06 above.
- (preview06) **`where T : new()` is removed** from the methods that map rows to a model, so a type that cannot be mapped throws `InvalidOperationException` at the call. `Map<int>()` and the like now throw (use `ExecuteScalar<T>()`), and `RowMap<T>.Default` is a property. See Preview 06 above.
- (preview06) **Constructor binding changes how some types are built.** A struct with one declared public constructor is built through it, a missing constructor-parameter column gives the parameter's declared default, and a `NULL` no longer overwrites a member the C# type declares non-nullable (`string Name { get; set; } = "";` keeps `""`; declare `string?` to get `null`). See Preview 06 above.
- Mapped Channel and Dataflow overloads: a mapping failure now faults the target when `complete` is `true`; the target is never completed or faulted before the reader is released; `ArgumentNullException.ParamName` for a null target is `"target"`; and a cancelled mapped async channel call succeeds only if the reader had already reported the end of the results, otherwise it throws `OperationCanceledException`.

## Known limitations in this preview

- `Retrieve()` followed by `DequeueAs<T>()` is a two-pass route: rows are copied into `object[]` and mapped as they are drained. It is slower and allocates more than a direct `Map<T>()` at larger sizes. For typed results prefer `Map<T>()` or `ResultsBuffered<T>()`.
- The unmapped `ToChannel` overloads can still lose the row that was in flight when a read fails while the target is full. The cause is in the underlying channel library.
- Output parameters can be sent, but their values cannot yet be read back after the call. Providers other than SQL Server supply no real parameter names yet, so `AddParam(search.Author)` uses the last member as written there (a SQL Server procedure is matched to its real names).
- `MappedQuery<T>` has `FirstOrDefault` and `SingleOrDefault` but no throwing `First` or `Single`: check the result for `null`.
- A missing column for a `required` property is reported at the first row, so an empty result does not report it. `DequeueAs<T>()`, `DataTable.To<T>()`, `ToChannel` and the Dataflow methods know the columns before any row and report it as soon as they have them, even when no row follows.
- Benchmarks and tests cover the in-memory provider, SQLite and SQL Server LocalDB. Feedback from other providers and workloads is welcome.
